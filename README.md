# SQL-Portfolio-Baseball
Why Baseball?

Most database examples use familiar business databases—customers, products, orders, employees—the sort of data found in a sample database such as Northwind.

My database work takes a different approach. I work with historical baseball play-by-play data because it presents many of the same challenges found in business data, while giving me a subject I genuinely enjoy exploring.

A baseball event rarely has meaning by itself. A batter coming to the plate with the bases empty in the first inning is a very different situation from that same batter coming up in the ninth inning with runners on base and the outcome of the game at stake. To understand what happened, you need to consider the surrounding circumstances.

Business data works much the same way. A customer or prospect is not simply a row in a table. Their position in the sales process, previous interactions, associated opportunities, and other data can change the significance of that record.

That's what I enjoy about working with relational databases: taking individual records and connecting them to the circumstances around them to answer a more meaningful question.

My baseball database contains more than one million play-by-play records. I use Microsoft Access and SQL to join tables, build queries, filter records, identify patterns, and investigate questions that aren't answered by simply looking at an individual record.

The subject happens to be baseball. The database skills are much more general.
